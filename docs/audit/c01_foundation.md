# Cluster 01 — Foundation Audit (Domains 1-8)

## Summary

This cluster covers the foundational data model of Smart Farmer: Account/Farmer, Farm, Plot, Crop, Crop Variety, Crop Cycle, Crop Stages, and Crop Calendar (84 scenarios total). The core CRUD backbone — registration/login/tokens, Farm and Plot creation/editing/soft-deactivation, and the CropCycle lifecycle (create -> sowing -> stage transitions -> close) — is unusually mature and well-tested: 40 backend "Complete" phases, hundreds of passing pytest cases, and a codebase that is deliberately self-documenting about its own honesty tradeoffs (docstrings explicitly state what was NOT built rather than silently omitting it). The most serious finding is a genuine security bug: password reset (`reset_password`, `auth_service.py:197-220`) requires only a phone number with zero identity verification, self-documented in-code as an account-takeover vector — classified BROKEN, not merely incomplete. Two structural gaps recur across domains: (1) there is no "active/current farm" session concept anywhere client or server — every call takes an explicit `farm_id`/`plot_id`, which is a deliberate stateless design rather than a bug, and (2) automation is consistently conservative-by-design — the codebase repeatedly chooses to expose read-only advisories (weather-task cross-reference, AI-suggested-stage columns) rather than silently auto-mutate farmer data, and documents this choice inline every time. Domain 8 (Crop Calendar) and parts of Domain 7 (biological sub-stages like germination, land preparation, post-harvest) and Domain 5 (variety-driven automation) are the weakest areas — largely explicit, documented deferrals rather than abandoned/broken work. Two real modeling gaps were found: no constraint prevents two concurrently-ACTIVE crop cycles on one plot (D6-07), and `CropStageDefinition` (a 6-stage per-crop reference table) is completely disconnected from the actual `cultivation_status` lifecycle enum that drives the app — it is used only for financial ledger tagging, which could easily mislead a future auditor who checks only that table.
