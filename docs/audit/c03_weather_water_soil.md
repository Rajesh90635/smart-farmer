# Audit: Domains 14-20 — Weather, Weather Risk, Weather Automation, Water, Irrigation, Soil, Soil Testing

Summary: This codebase has a genuinely real, well-tested weather pipeline (Farm location → `OpenMeteoProvider`/`FakeWeatherProvider` → `WeatherSnapshot` cache → farmer, `backend/app/services/weather_service.py`) with honest unavailable/stale handling, and two separate deterministic rule layers — `weather_alert_rules.py` (background notifications: rain/heavy-rain/wind/heat/cold/spray-warning, dedup'd via `Notification.dedup_key`) and `weather_action_rules.py` (Phase 37 farmer-facing SAFE/CAUTION/UNSAFE/UNKNOWN advisories for spray/irrigation/harvest, plus a forecast-window search) — both genuinely differentiated and cross-referenced in `docs/WEATHER_ALERT_RULES.md`/PROJECT_STATUS.md. Task↔weather integration is deliberately **read-only/advisory-only** (`weather_advisory` attached to a pending SPRAYING task's API response, never altering status/due_date — `task_service.py`), and irrigation-task auto-creation, modification, or postponement from weather does **not exist by design** (`Task` model docstring: only farmer-created tasks are supported; no crop-calendar/agronomic-rule dataset exists to drive auto-tasks). Beyond this, the picture drops off sharply: hourly forecast, frost/storm/cyclone/hail/flood/drought classification, soil moisture/sensor data, any dedicated Water model (source/availability/shortage/waterlogging/history), any Irrigation activity/pump-failure log, and the **entire Soil Testing domain (pH/N/P/K/organic carbon/EC/micronutrients/lab report/reminders)** are all completely absent from the schema — the only soil/irrigation data anywhere is two free-text `Plot.soil_type`/`Plot.irrigation_type` strings (`backend/app/models/plot.py:48-49`), explicitly documented as a placeholder pending a real taxonomy. A genuine documentation/code mismatch was found: `open_meteo_provider.py`'s own docstring claims parsing is "tested against a static fixture — see tests/test_weather_provider.py," but that test file does not exist anywhere in the repository and no test references `OpenMeteoProvider` at all — the real provider's field-parsing logic has **zero** test coverage, on top of the already-disclosed fact that the live Open-Meteo API has never been reached from this build sandbox.
