# C13 — Governance, Farm Brain, and Security Audit (Domains 88–98, 100)

This audit covers Data Provenance (88), Rule Versioning (89), Provider Abstraction (90), AI Governance (91), Farm Brain (92), Daily Farm Brief (93), What Changed (94), Risk Dashboard (95), Season Comparison (96), Season Closure (97), Historical Learning (98), and Security/Privacy/Audit (100) against the real code in `C:\FARMER_APP\smart-farmer-offline-sync-verified\smart-farmer`. The headline picture is uneven but honest: this project has genuinely strong, disclosed provider-abstraction architecture (Weather, AI/vision, Assistant-AI, and OCR all have real ABC interfaces plus at least one working or honestly-stubbed implementation), a real append-only `AuditLog` used from 27+ services, a versioned typed `ConsentRecord`/`CaseConsent` system, and a passing 9-endpoint cross-farmer isolation sweep (`test_phase40_integration.py::test_cross_farmer_isolation_holds_across_the_entire_integrated_surface`). Against that, several higher-level aggregation concepts the checklist assumes exist do not: there is no farm-wide "Farm Brain" or "Risk Dashboard" (risk is strictly per-crop-cycle via `RiskScoreScreen`/`crop_risk_service.py`), no "What Changed" diffing feature anywhere (notifications are rule-triggered per-event, never a stored-snapshot diff), `get_daily_summary` (the closest real "Daily Farm Brief") omits disease/pest actions, irrigation, crop-stage actions, and finance entirely, and neither weather-alert nor crop-risk "rules" carry any version/effective-date/region/stage metadata — they are plain deterministic Python functions. Season Comparison and Season Closure have real, working endpoints but narrower field coverage than the checklist (no variety/yield/disease/weather-impact comparison; no lessons-learned or disease/weather snapshot at closure). AI Governance has solid model/version/confidence capture on `AIAnalysis`, but farmer-correction/false-positive/false-negative tracking is either scoped only to a *different* subsystem (Advisory/Assistant feedback, not the disease-detection pipeline) or entirely unwired (`ai/evaluation.py` is a dormant framework fed no real data). Security (domain 100) is the strongest area: real JWT auth, dependency-based RBAC, consistent farmer-ownership (`get_owned`) checks returning 404-not-403 to prevent ID enumeration, scoped expert case-assignment + photo-grant access, and a passing security/integration test suite (11/11 passed when run) — but rate limiting covers only login/reset-password (in-memory, single-process, not wired globally or to uploads), and there is no GDPR-style data-export/deletion/anonymization feature at all.
