# Cluster 12 Audit — Notifications & Offline/Sync (Domains 78–87)

Summary: The notification system is real but narrow — it covers exactly one live trigger path (weather, pulled on-demand from `GET /farms/{id}/weather` → `weather_alert_orchestration_service.py`) plus one reused path for expert-case events (`case_service.py::_notify_case_event`); deduplication (DB unique constraint on `(farmer_id, dedup_key)`), read-state, and preference-gating are all solidly implemented and test-verified (`backend/tests/test_notifications.py`, 12/12 passing, re-run this session). Task/Market/Payment/Dispute/Stock/Soil/Disaster/Sync/Security notifications and any notion of notification expiry are genuinely absent — confirmed by grep, not assumed. The single biggest structural finding, confirmed by direct code reading across `mobile/lib/features/`: **offline/sync infrastructure (`PendingUploadQueue`, `SyncCoordinator`, `NetworkStatusChecker`) is scoped exclusively to crop-photo uploads** — Farm/Plot/Crop/Task/Expense/Harvest/Notes have zero offline queueing anywhere (grep across `lib/features/farm|task|harvest|ledger` for queue/offline references returns nothing outside `crop_photo/`), and no `Observation`/`Note`/`Diary` model exists in the backend at all. Within the one offline path that does exist, this session found a real, demonstrable bug: the queue's own two terminal "needs manual action" states (`authenticationRequired`, `retriesExhausted`) are permanently excluded from `retryable` (`pending_upload_queue.dart:207-215`) and **nothing anywhere — no app restart, no re-login, no UI screen — ever reads `needsManualAction` or moves an item back to retryable**, despite the code's own comments explicitly promising "the farmer can still act on it ... via the existing UI retry path" (line 79-81) — that path does not exist (confirmed by a repo-wide grep). This makes conflict resolution, job-level idempotency, and dead-letter recovery/visibility the weakest areas of this cluster. Flutter SDK was unexpectedly available this session (contrary to `PROJECT_STATUS.md`'s disclosed "no Flutter SDK" limitation for every prior phase) — `flutter test test/features/crop_photo/pending_upload_queue_test.dart test/features/notifications/notification_models_test.dart` was actually run and all 17 tests passed, upgrading several mobile-side rows from IMPLEMENTED to VERIFIED that the project's own docs assumed were unverifiable.
