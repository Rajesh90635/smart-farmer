# C05 Audit — Disease, Pest, AI Diagnosis, Image Quality, AI Confidence, Unknown Diagnosis (Domains 27-32)

This audit covers domains 27 (Disease), 28 (Pest), 29 (AI Diagnosis), 30 (Image Quality), 31 (AI Confidence), and 32 (Unknown Diagnosis) against the real code in `backend/app` and `mobile/lib/features/crop_photo`. The project's AI is a fully-built **provider-abstraction architecture** (`ModelProvider` -> `NotConfiguredModelProvider` -> `PredictionValidator` -> `AIAnalysis`) with **zero real trained disease/pest model**: `NotConfiguredModelProvider` (backend/app/services/ai/not_configured_provider.py) is the only implementation wired into production and always returns `available=False`, so every real analysis in this environment resolves to `AI_UNAVAILABLE` — this is honestly documented (docs/DISEASE_MODEL.md, docs/AI_MODEL_PROVIDER.md), not hidden. The pipeline itself (quality gate, confidence classification, safety validator, expert-case linkage, treatment/follow-up tracking, health timeline, crop risk score) is thoroughly built and tested with a **fake provider** to prove correctness end-to-end. The single biggest structural finding is that **Pest is not modeled anywhere as a concept distinct from Disease** — there is no `PestClass`, no pest result status, no pest photo/diagnosis/history/recommendation of any kind (confirmed by repository-wide search); the entire "crop health" system is disease-only. Two backend test runs were executed live in this session (149 backend tests across `test_ai_analysis`, `test_ai_contract`, `test_ai_localization`, `test_ai_model_components`, `test_crop_photos`, `test_treatments`, `test_cases`, `test_crop_risk`, `test_health_timeline`, `test_image_pipeline`, `test_case_photo_access` — all 149 passed) and one Flutter test run (`flutter test test/features/crop_photo/` — all 34 passed), so VERIFIED statuses below are backed by tests actually re-run in this session, not assumed from documentation.

## Top structural findings

1. **Pest is entirely absent as a domain** — no `PestClass`, no pest result status, no pest photo/diagnosis/history/recommendation/follow-up anywhere in models, schemas, services, repositories, or the API (domain 28 is MISSING end-to-end).
2. **No real trained AI model exists** — `NotConfiguredModelProvider` is the only wired `ModelProvider`; every real analysis today resolves to `AI_UNAVAILABLE`. The surrounding pipeline (confidence classification, safety validator, quality gate) is fully built and tested against a fake provider.
3. **Expert escalation on low confidence/unknown is farmer-confirmed, not automatic** — `requires_review` is set correctly, but no code path auto-creates a `CropHealthCase`; the farmer must tap "Request Expert Review."
4. **Treatment/pest recommendation is a deliberate, documented safety exclusion**, not an oversight — both the disease data model and the assistant's safety validator structurally block ever suggesting what chemical/treatment to apply.
5. **Image-quality checks cover blur/brightness only** — wrong framing, wrong plant part, duplicate photo, and old photo have no automated detection; framing/plant-part are mitigated only by pre-capture guidance text, and duplicate/old-photo detection is entirely absent (capture_timestamp isn't even populated).
