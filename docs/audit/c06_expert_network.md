# C06 Expert Network Audit — Domains 33-39

This audit covers the CropHealthCase expert/field-agent lifecycle (create -> route -> assign -> review -> recommend -> close), plus the separate, farmer-driven Treatment/Follow-up tracking system (Phase 34) and the farmer-created Task engine (Step 16). The single most important structural finding is that **there is no "expert recommendation" entity anywhere in this codebase**: `CaseReview` is a fixed-vocabulary diagnostic outcome (`confirmed`/`different_diagnosis`/etc.) plus optional free-text notes, deliberately with no medicine/dosage/treatment-plan field, and `TreatmentRecord`/`TreatmentFollowUp` (the closest thing to a "recommendation -> task -> follow-up -> reinspection" chain) are 100% farmer-initiated self-tracking records, never created by, or linked automatically to, an expert's review. This means domains 36-39 are largely built as a parallel, farmer-only workflow rather than the expert-driven workflow the checklist describes, and domain 35 (SLA) has a timer field that is set but never enforced because **no scheduler/cron/background worker exists anywhere in this project** (confirmed by repo-wide search — only comments disclosing its absence). All backend tests actually run for this audit (`test_cases.py`, `test_case_photo_access.py`, `test_treatments.py`, `test_professionals.py` — 48 tests) passed on a live Postgres instance.
